# 초기 설정 (Phase 1)

## 1. 텔레그램 봇
1. 텔레그램에서 **@BotFather** → `/newbot` → 이름/아이디 입력 → **토큰** 받기
2. 만든 봇에게 아무 메시지나 보내기
3. 브라우저에서 `https://api.telegram.org/bot<토큰>/getUpdates` 열기 → `"chat":{"id":숫자}` 의 숫자가 **chat id**

## 2. YouTube API 키
1. https://console.cloud.google.com → 새 프로젝트
2. "API 및 서비스 → 라이브러리"에서 **YouTube Data API v3** 사용 설정
3. "사용자 인증 정보 → 사용자 인증 정보 만들기 → API 키" (Phase 3에서 OAuth 추가 예정)

## 3. GitHub Secrets
레포 → Settings → Secrets and variables → Actions → New repository secret

| 이름 | 값 |
|---|---|
| `YOUTUBE_API_KEY` | 위 2번 키 |
| `TELEGRAM_BOT_TOKEN` | 위 1번 토큰 |
| `TELEGRAM_CHAT_ID` | 위 1번 chat id |
| `ANTHROPIC_API_KEY` | https://console.anthropic.com 에서 발급 (없으면 AI 정리 없이 기본 알림만 감) |
| `STATE_KEY` | 길고 임의의 문자열 (예: 비밀번호 생성기로 40자). 분실하면 저장된 상태를 복구할 수 없음 |

## 4. 실행
Actions 탭 → **collect** → Run workflow. 이후 매일 08시(KST)쯤 자동 실행.
첫 실행은 최근 30일 영상을 훑고(최대 20건 알림), 채널 확정 결과를 텔레그램으로 보냄. 채널이 틀렸으면 `config/channels.yaml`에 `handle`을 적어 수정.

## 5. 댓글 응모 승인 기능 (Phase 3) — YouTube OAuth
댓글/구독/좋아요를 **내 계정으로** 게시하려면 한 번만 로그인 승인이 필요하다.

1. Google Cloud 콘솔 → "API 및 서비스 → OAuth 동의 화면": 사용자 유형 **외부**, 앱 이름 아무거나, 본인 이메일 입력
2. **"앱 게시" 눌러 '프로덕션'으로 전환** (테스트 상태면 refresh token이 7일 뒤 만료됨). "확인되지 않은 앱" 경고가 뜨지만 본인 전용이라 무시해도 됨
3. "사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID" → 유형 **데스크톱 앱** → Client ID / Secret 복사
4. PC에서 (Python 3.12+):
   ```bash
   git clone https://github.com/neoibv/game_01 && cd game_01 && pip install -e .
   YOUTUBE_CLIENT_ID=... YOUTUBE_CLIENT_SECRET=... giveaway auth
   ```
   브라우저에서 응모에 쓸 Google 계정으로 로그인 → 출력된 토큰 복사
5. GitHub Secrets에 `YOUTUBE_CLIENT_ID`, `YOUTUBE_CLIENT_SECRET`, `YOUTUBE_REFRESH_TOKEN` 등록

이후 댓글 이벤트가 잡히면 텔레그램에 **댓글 초안 + [게시] [건너뛰기]** 버튼이 온다.
- 초안을 고치려면 그 메시지에 **답장(reply)** 으로 새 댓글을 보내면 됨
- 버튼을 누르면 `poll` 워크플로(15분마다)가 처리하므로 실제 게시는 최대 15~30분 뒤
- 매크로 금지 문구가 있거나 외부 로그인이 필요한 이벤트는 초안/버튼 없이 알림만 옴

## 6. 알림 형식
- **유튜브:** `<유튜브> 이벤트 확정` 한 메시지에 영상제목/제품/이벤트 기한/링크를 묶어서 보낸다. 응모 링크가 있거나 여러 시청자가 같은 양식으로 댓글을 단 영상만 "확정"이고, 근거가 아직 없는 영상은 72시간 동안 다시 확인한다.
- **응모 기록:** 알림 아래 버튼 메시지에서 직접 응모한 건은 [✅ 응모함]을 누르면 기록되고, 이후 모든 알림 하단에 '응모한 이벤트'와 결과 발표일이 붙는다(발표일 지난 뒤 7일, 발표일을 모르면 45일 후 사라짐).
- **관심없음:** [🚫 관심없음]을 누르면 그 이벤트의 제품 분류 단어(예: 헤드셋)가 차단돼 관련 이벤트가 더 나오지 않는다. 텔레그램에 `차단목록`, `차단해제 헤드셋`이라고 보내 확인·해제한다.
- 예전 형식의 알림 기록을 지우고 새 형식으로 다시 받으려면 Actions → collect → Run workflow에서 **reset_events**를 체크하고 실행한다. (응모 완료/승인 대기 건은 보존됨)

## 7. 유튜브 판정 기준과 보겸TV/보겸S
- **응모 방법은 빠짐없이:** 구독·좋아요·댓글·구글폼 등 필요한 행동을 모두 `응모 방법:`에 순서대로 적는다. 댓글이 하나라도 포함되면 댓글 초안과 [게시] 버튼이 온다(구글폼 등 직접 해야 할 것은 초안 메시지에 링크와 함께 표시).
- **제외되는 것:** 마감일이 지난 이벤트, 외부 서비스 회원가입·상품 구매·앱 설치·통신사 가입 같은 조건이 있는 이벤트(`config/filters.yaml`의 `exclude_signup_required`를 `false`로 바꾸면 `⚠️ 조건:` 표시와 함께 알림).
- **보겸TV/보겸S는 커뮤니티(게시물) 탭이 기준:** `config/channels.yaml`의 `community: true` 채널은 일반 영상을 보지 않고, 채널 게시물 중 `max_age_days`(14일) 이내 글만 읽는다. 게시물 본문의 응모 방법(구독·좋아요·알람설정·멤버십·댓글 키워드·줄 수·댓글 위치)을 AI가 그대로 추출해 `<유튜브> 이벤트 확정` 묶음에 `[보겸TV 게시물]`로 보여준다. 사후 공지("못 드렸습니다"), 채용 공고, 종료된 이벤트는 제외된다.
  - **공식 API가 없어** 채널의 공개 게시물 페이지를 읽는다(GitHub Actions에서 읽히는 것을 확인). 구조 변경이나 차단으로 못 읽으면 우회하지 않고 텔레그램으로 "커뮤니티 탭 수집 실패"를 알린다.
  - **게시글 댓글은 직접 작성:** 유튜브가 게시글 댓글 작성 API를 제공하지 않아, 키워드·줄 수를 맞춘 **초안만 보낸다**(복사해서 게시글에 직접 작성, 게시글 좋아요도 직접). 알림 설정(종)도 직접.
  - **게시물에 링크된 영상은 별도 이벤트:** 영상에 댓글을 달아야 하는 경우, 영상의 양식은 영상 말미에서 말로 안내돼(자막은 YouTube가 GitHub 서버 IP를 막아 못 받는다) 텔레그램으로 "영상 끝을 보고 양식을 답장해 주세요"를 보낸다. 답장하면(예: `보겸, 아이폰듀오 포함 2줄`) 초안과 [게시] 버튼이 오고, 승인하면 영상에 댓글 + 보겸TV·보겸S **두 채널 구독** + 영상 좋아요를 처리한다. 지난번 양식은 `같음`으로 재사용.
  - **멤버십:** 게시물은 대개 "절반은 구독자, 절반은 멤버십 가입자에게"라 멤버십은 필수가 아니라 별도 당첨 풀이다(알림에 `💳 멤버십: 우대/권장`). 자동 가입은 하지 않는다.
- **이미 쓴 댓글 검수:** 댓글 초안(또는 양식 요청) 메시지에 `검수` + 쓰신 댓글로 **답장**하면(예: `검수` 줄바꿈 후 댓글) 필수 키워드·최소 줄 수를 확인해 ✅ 또는 ❌ + **수정 제안**(내용은 보존하고 빠진 키워드·줄만 보충)을 보내준다. 봇이 올린 댓글이면 [✏️ 수정 적용] 버튼으로 바로 수정한다. 직접 쓰신 댓글은 유튜브에서 댓글 ⋮ → 수정으로 고친다(지우고 새로 쓰면 중복 응모가 될 수 있음). 사용자의 기존 댓글을 자동으로 찾지는 못한다(게시글 댓글은 API가 없고, 영상 댓글은 수만 개라 특정이 어렵다).

## 8. 새 채널 발견 (덜 알려진 IT 유튜버)
`config/discovery.yaml`의 키워드로 YouTube를 검색해 **채널 목록에 없는 소규모 IT 유튜버**의 이벤트까지 찾는다.
- **어떻게:** 쿼리(`구독자 이벤트 키보드` 등)로 최근 14일 영상을 검색 → 제목·설명에 IT 키워드(이어폰·키보드·노트북 등)가 있는 영상만 → 구독자 수 `min_subscribers` 이상(스팸 제외) → **구독자 적은 채널부터** 최대 40개를 AI로 판정. 기존과 같은 기준(응모 링크 또는 다수 시청자의 같은 양식 댓글, 마감·가입조건 제외)을 적용한다.
- **알림:** `경쟁: 구독자 1,780 · 댓글 171개 · 🔭 새로 발견한 채널(앞으로 자동 감시)`처럼 경쟁 정도가 같이 나온다. 점수에도 반영돼 댓글이 적을수록(당첨 확률↑) 위로 올라간다.
- **자동 감시:** 이벤트가 확인된 채널은 `watch:` 목록(최대 `max_watched`=60)에 올라가 이후 매 실행마다 새 영상을 확인한다. 검색에 안 걸려도 놓치지 않는다.
- **비용/쿼터:** 검색은 쿼리당 YouTube API 100 unit이라 기본 10개 쿼리면 실행당 약 1,000 unit(하루 한도 10,000 중). AI 판정은 실행당 최대 40건. 쿼리는 **1~3단어로 짧게** 써야 한다(YouTube 검색은 단어를 모두 포함한 영상만 돌려주므로 긴 문장은 0건).
- **분야:** 기본은 IT(`allowed_categories: [it]`). `baby`, `gift_travel`을 추가하면 아기·출산용품, 기프티콘·여행 이벤트도 찾는다. 끄려면 `enabled: false`.

## 9. 제외 분야 (키보드 등)
`config/filters.yaml`의 `exclude_topics`에 든 단어(기본: 키보드·키캡·기계식·타건·텐키리스·독거미·축 종류 등)가 **제목·설명·경품**에 있으면 모든 소스(유튜브 전 채널·발견 검색·커뮤니티)에서 제외한다. 제목·설명에 걸리는 영상은 AI를 부르지도 않는다. 이미 알림이 나간 해당 이벤트는 다음 실행 때 자동으로 처리 대기가 끝나고(`skipped`), 텔레그램에 남은 [게시] 버튼은 눌러도 "처리할 수 없는 상태"라고 막힌다. 다른 분야를 빼려면 같은 목록에 단어를 추가하면 된다(예: `마우스`). 영어는 소문자로 비교한다.

## 10. YouTube API 할당량
하루 10,000 unit(태평양시 자정 초기화, 한국 시간 오후 4~5시). 새 채널 발견은 쿼리당 100 unit이라 기본 12개 쿼리면 실행당 약 1,200 unit이고, 나머지 수집까지 합쳐도 하루 2,000 안팎이다. 할당량이 넘치면(HTTP 429/403) 발견 검색은 그 자리에서 멈추고 **지금까지 찾은 것만** 알리며 텔레그램으로 한 번 경고한다(다른 수집은 그대로 진행). 쿼리를 늘리면 `max_queries_per_run`×100 unit이 더 든다. 개발 중 진단 실행도 같은 할당량을 쓴다.

## 11. 버튼 응답 속도 (watch)
**문제:** GitHub의 예약 실행(`schedule`)은 새 레포/저활동 레포에서 몇 시간씩 늦어진다(이 레포에서 `poll`을 "15분마다"로 설정했지만 실제로는 4~5시간 간격으로 돌았다). 그래서 [게시]·답장이 처리되기까지 몇 시간이 걸렸다.
**해결:** 초안·양식 요청을 보내면(`collect`) 또는 사용자가 버튼/답장을 처리시키면(`poll`) **`watch` 워크플로가 몇 시간 동안 켜져** 텔레그램을 롱폴링한다. 버튼을 누르거나 답장하면 즉시 버튼 로딩을 "접수됨 — 곧 처리됩니다"로 바꾸고 `poll`을 바로 깨워 보통 **30~60초 안에** 게시·응답이 끝난다.
- 켜지는 때: `collect`가 초안/양식 요청을 보냈을 때 300분, `poll`이 업데이트를 처리했을 때 180분. 이미 켜져 있으면 중복해서 켜지 않는다.
- 감시가 꺼진 뒤(예: 수 시간 뒤 오래된 버튼을 누를 때)에는 예전처럼 예약된 `poll`이 처리하므로 **몇 시간 걸릴 수 있다.** 급하면 Actions → **poll** → Run workflow를 직접 누르면 바로 처리된다.
- 공개 레포라 Actions 시간은 무료다. `watch`는 DB를 건드리지 않고 기다리기만 해서 `collect`/`poll`과 충돌하지 않는다.
